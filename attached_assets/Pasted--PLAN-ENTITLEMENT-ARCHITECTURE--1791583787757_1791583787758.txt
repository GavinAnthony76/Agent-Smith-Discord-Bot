==================================================
PLAN / ENTITLEMENT ARCHITECTURE
==================================================

IMPORTANT:

The LMOC / Agent Smith platform is being designed as a multi-tier product.

Features, limits, modules, Discord capabilities, analytics, AI usage, economy
features, role automation, channel automation and other capabilities may be
gated behind plans.

Current proposed plans are:

FREE
PRO
ULTIMATE

Billing is NOT currently enabled.

There is no checkout and no finalized pricing.

Do NOT implement payment processing simply because plan tiers exist.

Plan gating must work independently from billing so plans can currently be
assigned manually for testing/development.

==================================================
CURRENT PROPOSED PLAN POSITIONING
==================================================

FREE

Intended for a single/basic community.

Includes at minimum:

- core moderation
- onboarding
- basic roles
- audit log
- standard limits

PRO

Includes everything in FREE plus:

- higher usage / record limits
- expanded modules
- larger community allowances
- AI usage allowance
- additional configuration features

ULTIMATE

Includes everything in PRO plus:

- highest supported limits
- advanced modules
- priority/new feature access where configured
- larger-scale community capabilities

These tier definitions are PROPOSED.

Do not hardcode the marketing copy as permanent business rules.

Create a configurable entitlement matrix.

==================================================
PLAN DOWNGRADES
==================================================

Downgrades must be SAFE.

If:

ULTIMATE → PRO
or
PRO → FREE

do not:

- delete user data
- delete Discord channels automatically
- delete earned achievements
- remove moderation history
- destroy member XP
- erase inventory
- delete existing configuration

Instead:

preserve the data
disable new usage where required
mark features read-only/inactive
show Owner/Admin what exceeds the new entitlement

Example:

Guild has 10 feed sources.
Free permits 2.

After downgrade:

- preserve all 10 records
- keep 2 active according to configured policy
- mark 8 inactive/over-limit
- do not silently delete them

==================================================
MEMBER REWARD DOWNGRADES
==================================================

Do NOT automatically strip every member reward because the guild's plan changes.

Reward behavior must have explicit policy.

Possible policies:

PRESERVE_EARNED
DISABLE_NEW_GRANTS
REMOVE_AUTOMATED_ROLE

Default to the safest non-destructive option:

PRESERVE_EARNED
+
DISABLE_NEW_GRANTS

unless product policy explicitly says otherwise.

==================================================
CRITICAL DISTINCTION
==================================================

Always evaluate access in this order:

1. Is the guild/server entitled to the feature?
2. Is the feature enabled for this guild?
3. Is the feature configured correctly?
4. Does the individual user have permission?
5. Does the user's role/level/status qualify?
6. Is the requested resource within the plan limit?
7. Is the requested action safe?

Only then execute.

Conceptually:

SERVER PLAN
     ↓
FEATURE ENTITLEMENT
     ↓
MODULE ENABLED
     ↓
USER AUTHORIZATION
     ↓
MEMBER QUALIFICATION
     ↓
RESOURCE LIMIT
     ↓
SECURITY CHECK
     ↓
ACTION
